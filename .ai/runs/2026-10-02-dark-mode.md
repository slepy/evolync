# Execution plan — Dark mode (System / Light / Dark)

Source doc: .ai/specs/2026-10-02-dark-mode.md
Spec PR: #12 (design-only; implementation ships here)

## Goal

Give instructors and students a Settings → Appearance choice (System / Light / Dark, default System) backed by semantic theme colors, with light mode staying visually identical to today.

## Scope

- `tamagui.config.ts`: semantic theme keys added to every `light*` and `dark*` theme (light values equal today's palette tokens).
- `src/core/storage.ts` (extracted from i18n), `src/core/theme/` (store, persistence, resolution hooks) + unit tests.
- Root wiring in `app/_layout.tsx` and nested `_layout.tsx` files (navigation theme, status bar, no `#F8FAFC` literals).
- Color migration of `app/` and `src/modules/**` UI from static palette tokens / literals / `theme.<paletteToken>.val` reads to semantic keys; fix `$softGrayBark`.
- `ThemeSwitcher` in `src/core/components/`, rendered in `app/user/settings.tsx`; 4 translation keys in `en.json` + `pl.json`.
- `scripts/check-theme-colors.js` + `npm run check:theme`, appended to `validation.commands`.

## Non-goals

- 3D canvas, scene lights, model materials, gizmo colors (spec Q3).
- Solid brand accent fills (`$imperialRed`, `$jadeGreen`, `$chineseGold`, … with white text) — kept as-is (spec Q4).
- Native splash screen theming; synced (per-user) theme preference.
- Any data, repository, sync or schema change.

## Semantic key set (final)

Light values are exactly the palette value each key replaces, so light mode is pixel-identical. Extra keys beyond the spec's initial table exist only to keep that guarantee (spec allows extending the initial set).

| Key | Light | Dark | Replaces |
|---|---|---|---|
| `background` (existing) | `#F8FAFC` | `#0F172A` | `#F8FAFC` literals, `$pearlWhite` as background |
| `surface` | `#FFFFFF` | `#1E293B` | `$pearlWhiteLight`, `"white"` surfaces |
| `surfaceTranslucent` | `rgba(255, 255, 255, 0.7)` | `rgba(30, 41, 59, 0.7)` | card/sheet `rgba(255,255,255,0.7)` literals |
| `textPrimary` | `#0F172A` | `#F8FAFC` | `$inkBlack` |
| `textBody` | `#1E293B` | `#E2E8F0` | `$inkBlackLight` |
| `textSecondary` | `#64748B` | `#CBD5E1` | `$softGrayDark` |
| `textMuted` | `#94A3B8` | `#94A3B8` | `$softGray` as text |
| `fillMuted` | `#94A3B8` | `#475569` | `$softGray` as fill/border |
| `borderStrong` | `#CBD5E1` | `#475569` | `$softGrayLight` as border |
| `fillStrong` | `#CBD5E1` | `#334155` | `$softGrayLight` as fill |
| `borderSubtle` | `#E2E8F0` | `#334155` | `$softGrayLighter` as border |
| `fillSubtle` | `#E2E8F0` | `#1E293B` | `$softGrayLighter` as fill |
| `successSurface` / `successText` | `#d6f1e8` / `#047857` | `#022C22` / `#6EE7B7` | `$jadeGreenLighter` / `$jadeGreenDark` (text) |
| `dangerSurface` / `dangerText` | `#fed1d1` / `#B91C1C` | `#450A0A` / `#FCA5A5` | `$imperialRedLighter` / `$imperialRedDark` (text) |
| `dangerSurfaceSubtle` | `#FEF2F2` | `#2A0A0A` | `ErrorBanner` literal |
| `warningSurface` / `warningText` | `#fbefd2` / `#D97706` | `#451A03` / `#FCD34D` | `$chineseGoldLighter` / `$chineseGoldDark` (text) |
| `infoSurface` / `infoText` | `#cffafe` / `#0E7490` | `#083344` / `#67E8F9` | `$chineseCyanLighter` / `$chineseCyanDark` (text) |
| `primarySurface` / `primaryText` | `#dbeafe` / `#1E40AF` | `#172554` / `#93C5FD` | `$darkBlueLighter` / `$darkBlue` (icons) |
| `roseSurface` | `#ffe4e6` | `#4C0519` | `$chineseCoralLighter` |

Dark text values on `background`/`surface` all exceed WCAG AA 4.5:1 (e.g. `#CBD5E1` on `#1E293B` ≈ 9.9:1; `#94A3B8` on `#0F172A` ≈ 7.0:1; `#94A3B8` on `#1E293B` ≈ 5.7:1); `*Text` keys on their dark surfaces are ≥ 6.3:1. Dark success/info/primary surfaces were darkened from the spec draft so the kept brand accent icons (`$jadeGreen`, `$chineseCyan`, `$darkBlueLight`) stay ≥ 3:1 on them.

Undefined tokens fixed during migration: `$softGrayBark` (orders), `$blackInk` (register), `$white` (OptionsSheet). Small light-mode deltas, intentionally accepted: a few off-palette hex literals (`#6B7280`, `#888`, `#4B5563`, `#FAFAFA`, `#1A1A2E`) now use the nearest semantic key; `ErrorBanner` message text uses `dangerText`; disabled `NotesModeCard` uses `surfaceTranslucent`.

## Implementation Plan

### Phase 1 — Foundation
1. Extract the storage wrapper to `src/core/storage.ts`; i18n imports it.
2. Add the semantic keys to all `light*` / `dark*` themes in `tamagui.config.ts`.
3. Add `src/core/theme/` (store, `loadThemePreference`, `useThemePreference`, `useResolvedTheme`) + unit tests.
4. Wire root/nested layouts to theme values, navigation theme and `StatusBar`; await `loadThemePreference()` before hiding splash; resolved theme still forced to `light`.

### Phase 2 — Color migration
5. `core` components.
6. `auth` + `settings` screens.
7. `dashboard`, `notifications`.
8. `school`, `students`, `organization`.
9. `attendance`, `events`, `grading`.
10. `payments`, `orders` (fix `$softGrayBark`), `inventory`.
11. `techniques`, `tags`, `threed` panels and sheets (canvas excluded).

### Phase 3 — Setting
12. `ThemeSwitcher` in `src/core/components/`, rendered in Settings under Language; 4 translation keys.
13. Remove the `light` force; default `system`.

### Phase 4 — Guardrail
14. `scripts/check-theme-colors.js` + `npm run check:theme`; append to validation commands.

## Risks

- Broad styling diff (~100 files) — mitigated by light values equal to current palette; the codemod classifies each usage by prop (text / border / fill) and the diff is re-read.
- Manual per-screen dark QA (iOS/Android/web) is not possible in this environment (no test-env descriptor) — left as `needs-qa`.
